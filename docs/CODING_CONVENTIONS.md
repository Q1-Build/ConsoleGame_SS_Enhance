# SS_Enhance 코딩 컨벤션

이 문서는 C++17 코드 스타일, 설계 원칙, 소유권, 오류 처리와 한글 주석 규칙을 정의한다.
Modern C++ 관용 스타일과 C++ Core Guidelines의 안전성 및 RAII 원칙을 따른다.

## SOLID 적용

### SRP

- 클래스가 변경되는 이유는 하나여야 한다.
- 입력, 규칙 계산, 상태 변경과 렌더링을 한 함수에서 동시에 처리하지 않는다.
- 클래스가 빠르게 커지면 메서드 분할보다 책임 분리를 먼저 검토한다.

### OCP

- 새 장면이나 검 등급을 추가할 때 핵심 로직의 거대한 `switch`를 계속 키우지 않는다.
- 실제 변화 가능성이 확인된 지점에만 다형성이나 데이터 테이블을 도입한다.
- 단순 값 객체마다 형식적인 인터페이스를 만들지 않는다.

### LSP

- 인터페이스 구현은 호출자가 기대하는 입력, 출력과 수명 주기 계약을 지킨다.
- 기반 동작을 무효화하기 위한 빈 구현이나 예외 던지기를 금지한다.

### ISP

- 장면이 전체 엔진 객체를 받지 않도록 입력, 렌더링과 난수를 작은 역할로 분리한다.
- 사용하지 않는 함수까지 구현하게 하는 대형 인터페이스를 만들지 않는다.

### DIP

- 게임 규칙과 장면은 구체적인 Windows 구현보다 필요한 계약에 의존한다.
- 난수, 입력과 시간처럼 테스트를 어렵게 만드는 외부 요소는 경계에서 주입한다.
- 교체나 테스트 필요성이 없는 내부 값 객체에는 불필요한 인터페이스를 만들지 않는다.

## 명명 규칙

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 클래스, 구조체, 열거형, 타입 별칭 | `PascalCase` | `ForgeSession`, `SceneType` |
| 함수, 메서드 | `PascalCase` | `CalculateChance()`, `Render()` |
| 지역 변수, 매개변수 | `camelCase` | `deltaSeconds`, `forgeCost` |
| private 멤버 | `camelCase_` | `currentHeat_`, `playerProgress_` |
| 컴파일 타임 상수 | `kPascalCase` | `kScreenWidth`, `kMaxHeat` |
| `enum class` 항목 | `PascalCase` | `SceneType::Forge` |
| 인터페이스 | 역할 앞에 `I` | `IScene`, `IRandomProvider` |
| 파일과 폴더 | 핵심 타입과 같은 `PascalCase` | `ForgeSession.h`, `Rendering/` |

- 불리언은 `is`, `has`, `can`, `should`처럼 질문으로 읽히게 명명한다.
- 단위가 중요한 값은 이름에 단위를 포함한다: `deltaSeconds`, `durationMs`.
- 컬렉션은 복수형으로 명명한다: `strikeScores`, `particles`.
- 의미 없는 이름인 `data`, `temp`, `obj`, `manager`와 불명확한 축약어를 피한다.
- 짧은 반복 인덱스 `i`와 좌표 `x`, `y`는 제한적으로 허용한다.

## 파일과 선언

- 한 헤더에는 하나의 핵심 클래스 또는 밀접한 값 타입 묶음만 둔다.
- 선언은 `.h`, 구현은 `.cpp`에 둔다.
- 템플릿과 짧고 자명한 접근자만 필요한 경우 헤더에 구현할 수 있다.
- 헤더는 독립적으로 컴파일 가능해야 하며 사용하는 타입을 직접 포함한다.
- 포함 순서는 `자기 헤더 → 프로젝트 헤더 → 표준 라이브러리 → 플랫폼 헤더`로 구분한다.
- 헤더에는 `#pragma once`를 사용한다.
- 순환 참조를 금지하고 소유하지 않는 타입은 가능한 경우 전방 선언한다.
- 헤더와 전역 범위에서 `using namespace`를 사용하지 않는다.
- 플랫폼 매크로 오염은 `NOMINMAX`처럼 필요한 범위에서 명확히 제한한다.

## 포맷

- 들여쓰기는 공백 4칸이며 탭과 섞지 않는다.
- 중괄호는 선언문 다음 줄에 두는 Allman 스타일을 사용한다.
- 조건문과 반복문 본문이 한 줄이어도 중괄호를 작성한다.
- 한 줄에는 하나의 명령문만 작성한다.
- 긴 식은 연산자의 의미가 보이도록 여러 줄로 정렬한다.
- 포인터와 참조 기호는 타입에 붙인다: `Sword* sword`, `const Sword& sword`.
- 파일 끝에는 빈 줄 하나를 유지하고 후행 공백을 남기지 않는다.

```cpp
if (currentHeat >= kMinResonanceHeat)
{
    StartResonance();
}
```

## 타입과 표현식

- C 스타일 캐스트를 금지하고 의도에 맞는 C++ 캐스트를 사용한다.
- `NULL`과 숫자 `0` 대신 `nullptr`을 사용한다.
- 열거형은 `enum class`를 사용한다.
- 변하지 않는 값, 매개변수와 메서드에는 적극적으로 `const`를 적용한다.
- 타입이 명확하거나 반복자를 다룰 때 `auto`를 사용한다.
- 숫자 또는 반환 의미가 흐려지는 곳에서는 실제 타입을 작성한다.
- 매직 넘버는 이름 있는 `constexpr` 상수나 규칙 데이터로 옮긴다.
- 컴파일 시간에 계산 가능한 순수 함수와 값에는 가능한 한 `constexpr`를 사용한다.
- 부동소수점 값에는 의도를 드러내는 접미사를 쓴다: `1.0f`.
- `consteval`과 `std::span`은 C++20 기능이므로 사용하지 않는다.

## 함수

- 함수는 하나의 책임과 한 단계의 추상화 수준을 유지한다.
- 함수 이름은 동작과 결과가 드러나는 동사로 시작한다.
- 상태를 바꾸지 않는 조회 함수는 `const`로 선언한다.
- 결과를 무시하면 논리 오류가 되는 함수에는 `[[nodiscard]]`를 사용한다.
- 단순 접근자와 의도적으로 버릴 수 있는 반환값에는 `[[nodiscard]]`를 남용하지 않는다.
- 출력 매개변수보다 반환값을 우선한다.
- 여러 결과는 의미 있는 결과 구조체로 반환한다.
- 호출 의미를 감추는 불리언 매개변수는 열거형이나 별도 함수로 바꾼다.
- 정상적인 게임 흐름 제어에 예외를 사용하지 않는다.
- 실제로 예외가 발생하지 않음을 보장하는 함수에만 `noexcept`를 작성한다.
- 소멸자와 이동 연산은 가능한 한 `noexcept`를 유지한다.

## 매개변수 전달

| 목적 | 방식 |
| --- | --- |
| 기본 타입, 열거형, 작은 값 타입 | 값 `T` |
| 크거나 복사 비용이 높은 읽기 전용 객체 | `const T&` |
| 호출자의 객체를 수정하지만 소유하지 않음 | `T&` |
| null을 허용하는 선택적 비소유 객체 | `T*` |
| 단독 소유권 전달 | `std::unique_ptr<T>` 값 |
| 복사 가능한 값을 내부에 저장 | 값으로 받은 뒤 `std::move` |
| rvalue만 허용하는 의미가 명확함 | `T&&` |

- 읽기 전용 문자열을 소유하지 않는 짧은 호출에는 `std::string_view`나 `std::wstring_view`를 사용할 수 있다.
- `string_view`를 원본보다 오래 저장하거나 임시 문자열에서 얻은 뷰를 멤버로 보관하지 않는다.
- C++17의 연속 범위는 컨테이너 `const&` 또는 반복자 쌍으로 전달한다.
- 포인터와 길이를 별도로 전달하면 관계와 유효 범위를 한글 주석으로 명시한다.
- 전달 방식은 크기보다 소유권과 수정 가능성을 먼저 표현해야 한다.
- 전달 참조는 완벽 전달이 실제로 필요한 범용 코드에서만 사용한다.

## 메모리와 소유권

- 직접적인 `new`, `delete`, `malloc`, `free`를 금지한다.
- 단독 소유는 값 또는 `std::unique_ptr`로 표현한다.
- 동적 객체는 `std::make_unique` 또는 `std::make_shared`로 생성한다.
- `std::shared_ptr`는 실제 공유 소유권이 있을 때만 사용한다.
- 공유 포인터 사이의 관찰 방향은 필요하면 `std::weak_ptr`로 순환 참조를 막는다.
- 상위 객체가 수명을 보장하는 비소유 관계는 참조 또는 포인터를 우선한다.
- 필수 비소유 객체는 참조, 선택적 비소유 객체만 포인터로 표현한다.
- 컨테이너와 문자열은 표준 라이브러리 타입을 우선한다.
- 자원 획득과 해제는 RAII 객체의 생성자와 소멸자에 묶는다.

## 클래스 설계

- 멤버 변수는 기본적으로 `private`으로 둔다.
- 단순 전달용 값 타입만 `struct`의 public 멤버를 허용한다.
- 접근자를 기계적으로 만들지 않고 클래스가 보장할 행위 중심 메서드를 제공한다.
- 생성자가 끝난 객체는 즉시 유효해야 한다.
- 단일 매개변수 생성자와 변환 연산자는 기본적으로 `explicit`을 사용한다.
- Rule of Zero를 기본으로 한다.
- 특별 멤버 함수 하나를 직접 정의하면 Rule of Five 전체 의미를 검토하고 `= default` 또는 `= delete`로 명시한다.
- 복사가 의미 없는 자원 소유 클래스는 복사 생성자와 복사 대입을 삭제한다.
- 상속보다 합성을 우선하고 실제 다형성 경계에서만 인터페이스를 사용한다.
- 함수 재정의에는 반드시 `override`를 작성한다.
- 더 이상 파생하거나 재정의할 의도가 없을 때 설계 계약으로 `final`을 사용한다.

## 계약과 오류 처리

- 내부 프로그래밍 오류와 깨지면 안 되는 불변 조건은 Debug 빌드의 `assert`로 탐지한다.
- null 불허, 인덱스와 도메인 값 범위 같은 전제 조건을 검증한다.
- Release에서 사라지면 안 되는 상태 변경이나 결과 저장을 `assert` 안에 넣지 않는다.
- 사용자 입력, 파일 오류와 복구 가능한 런타임 실패에 `assert`를 사용하지 않는다.
- 복구 가능한 실패는 조건문, 결과 구조체나 `std::optional`로 호출자에게 전달한다.
- 실패를 조용히 무시하지 않고 복구하거나 상위 계층에 전달한다.
- 전용 Assertion 매크로를 도입하면 플랫폼 동작과 Release 정책을 한 곳에 문서화한다.

## 가독성

- 짧은 코드보다 의도가 바로 읽히는 코드를 우선한다.
- 중복 제거를 위해 서로 다른 책임을 억지로 합치지 않는다.
- 설명이 필요한 한 줄 표현보다 이름 있는 중간 변수와 작은 함수를 사용한다.
- 주석은 코드의 동작보다 구현 이유와 계약을 설명한다.
- 기존 파일을 수정할 때 주변 코드와 스타일을 일관되게 정리한다.

## 한글 주석 규칙

새로 작성하거나 구조를 변경하는 코드에는 중요한 의도와 계약을 설명하는 한글 주석을 작성한다.
클래스명, API명과 표준 기술 용어는 의미가 더 명확하면 영어 원문을 함께 사용할 수 있다.

### 주석 밀도

- 모든 `.cpp`에는 구현 의도를 설명하는 한글 주석이 최소 1개 있어야 한다.
- 80줄 이상의 `.cpp`는 주요 처리 구역마다 일반적으로 3개 이상의 의미 있는 주석을 둔다.
- 긴 함수에서는 입력 해석, 상태 갱신, 판정과 연출처럼 책임 단계가 바뀌는 지점에 주석을 둔다.
- 계산식은 숫자 나열보다 가중치, 보정 범위와 밸런스 의도를 설명한다.
- 장면 전환은 상태 확정 시점과 그 순서를 선택한 이유를 설명한다.
- 렌더링은 문자 좌표보다 깜빡임 방지, 피드백과 영역 구분 의도를 설명한다.
- 플랫폼 코드는 인코딩, API 격리, 자원 복원과 실패 가능성을 설명한다.
- 컨테이너 제거, 수명 관리와 최적화처럼 대안이 있는 선택은 이유를 설명한다.
- 자명한 접근자, 단순 대입과 반복문의 각 줄에는 주석을 달지 않는다.
- 책임이 이동하면 관련 주석도 새 위치로 이동하거나 다시 작성한다.

### 반드시 주석을 작성할 위치

- 새 클래스와 인터페이스 선언 바로 위
- 외부 계층에서 호출하는 public API 계약 바로 위
- 새 `enum`, 주요 구조체와 값 객체 선언 바로 위
- 클래스의 프로퍼티 또는 멤버 변수 묶음 위
- 수명, 소유권, 단위와 유효 범위가 중요한 멤버 옆
- 확률 계산, 상태 전환과 보정 공식 등 핵심 게임 규칙 위
- Windows API, 콘솔 복구와 인코딩처럼 이유를 알기 어려운 플랫폼 코드 위
- 성능 최적화나 우회 코드처럼 선택 이유가 코드만으로 드러나지 않는 부분

### 문서 형식

- 클래스, 인터페이스, 주요 구조체와 public API에는 Doxygen 호환 `///` 주석을 사용한다.
- private 구현 세부사항, 멤버 묶음과 알고리즘 내부에는 `//` 주석을 사용한다.
- public API에는 필요에 따라 책임, 매개변수 범위, 반환 의미, 소유권과 실패 조건을 적는다.
- 자명한 접근자에 형식적인 Doxygen 주석을 반복하지 않는다.
- 헤더는 책임과 계약, 소유권, 범위와 수명을 설명한다.
- 소스는 알고리즘 선택 이유, 상태 변경 순서, 예외 분기와 연출 의도를 설명한다.

```cpp
/// 한 번의 제련 과정과 세 번의 타격 결과를 관리한다.
/// 화면 출력과 최종 강화 판정은 담당하지 않는다.
class ForgeSession
{
public:
    /// 경과 시간만큼 제련 상태를 갱신한다.
    /// @param deltaSeconds 이전 프레임 이후 경과한 초 단위 시간
    void Update(float deltaSeconds);

private:
    // 0~100 범위의 현재 검 온도다.
    float heat_ = 50.0f;

    // 타격별 정확도를 0~1 범위로 순서대로 저장한다.
    std::vector<float> strikeScores_;
};
```

코드를 한국어로 그대로 반복하거나, 구현과 맞지 않는 오래된 주석, 자명한 작업 설명과 긴 작업 일지는 피한다.
