# SS_Enhance 개발 절차

이 문서는 작업 시작부터 검증과 완료 판단까지의 공통 절차와 향후 확장 원칙을 정의한다.

## 작업 전

1. 루트 `AGENTS.md`와 작업 범위에 해당하는 `docs` 문서를 읽는다.
2. 관련 소스와 헤더를 읽고 현재 책임과 데이터 수명을 파악한다.
3. 변경할 책임이 어느 계층에 속하는지 결정한다.
4. 기존 클래스가 다른 책임까지 떠안는다면 메서드 분할보다 책임 분리를 먼저 검토한다.
5. 게임 규칙이나 UI 동작을 바꾼다면 `GAME_DESIGN.md`와의 일치 여부를 확인한다.

## 구현 중

- 새 기능의 순수 규칙과 결과 타입은 가능한 한 `Game/Domain`에 먼저 정의한다.
- 난수, 입력, 시간 등 외부 요소는 작은 계약으로 주입한다.
- 구체 장면 생성은 `GameApplication::CreateScene` 한 곳에서만 수행한다.
- 공통 시각 요소만 `GameHudRenderer`나 별도 렌더러로 추출한다.
- Windows 전용 기능은 `Platform/Console`에 구현하고 게임 계층에는 계약만 노출한다.
- 새 클래스, public API, 멤버 묶음과 핵심 로직에 코딩 컨벤션에 맞는 한글 주석을 작성한다.
- 새 `.cpp`와 `.h`를 `SS-Enhance.vcxproj`와 `SS-Enhance.vcxproj.filters`에 등록한다.
- 구조나 규칙이 바뀌면 관련 문서를 코드와 같은 변경에서 갱신한다.

## 검증 순서

1. 변경된 호출부와 계층 의존성을 정적 검색으로 확인한다.
2. Debug x64 빌드를 실행한다.
3. 새 컴파일 경고가 없는지 확인한다.
4. `git diff --check`로 공백 오류를 확인한다.
5. 변경 범위에 맞는 수동 플레이 또는 자동 테스트를 수행한다.
6. 한글 UI 변경 시 전각 문자 정렬, 박스 경계와 줄바꿈을 실제 콘솔에서 확인한다.

기본 빌드 명령은 다음과 같다.

```powershell
& MSBuild.exe SS-Enhance\SS-Enhance.vcxproj `
    /t:Build `
    /p:Configuration=Debug `
    /p:Platform=x64
```

## 완료 조건

- Debug x64 빌드 성공
- 새 경고를 추가하지 않음
- `git diff --check` 통과
- `Main.cpp`에 게임 로직을 추가하지 않음
- 각 클래스의 책임을 한 문장으로 설명 가능
- Domain이 Windows API, 입력과 렌더링에 의존하지 않음
- 입력, 상태 갱신, 판정과 렌더링의 경계가 명확함
- 새 핵심 클래스, public API와 멤버에 필요한 한글 주석 존재
- 모든 새 `.cpp`에 구현 의도 주석이 있고 긴 구현의 주요 처리 구역이 설명됨
- 중요한 반환값에 `[[nodiscard]]`가 적용됨
- 단일 매개변수 생성자에 필요한 `explicit`이 적용됨
- 소유권과 복사·이동 정책이 코드에서 명확함
- 내부 불변 조건과 복구 가능한 런타임 오류를 구분해 처리함
- 새 파일이 Visual Studio 프로젝트와 필터에 등록됨
- 변경된 구조와 게임 규칙이 관련 문서와 일치함

## 테스트 확장 원칙

- 순수 게임 규칙부터 자동 테스트를 추가한다.
- 같은 입력과 난수 값에 같은 결과가 나오는지 검증한다.
- 플랫폼 코드는 통합 테스트와 실제 Windows 콘솔 확인으로 검증한다.
- 렌더링은 화면 밖 쓰기, 전각 문자 점유와 정렬 같은 경계 조건을 우선 테스트한다.

## 다음 기능 확장 원칙

1. 새 기능의 규칙과 결과 타입을 먼저 정의한다.
2. 데이터 소유자와 수명을 문서화한다.
3. 필요한 외부 요소만 작은 인터페이스로 주입한다.
4. 장면과 표현을 추가한 뒤 공통 부분만 추출한다.
5. 보스전, 저장, 사운드 같은 대형 기능은 책임과 데이터 수명을 먼저 설계한다.
6. 구현과 함께 자동 테스트 범위를 넓힌다.

새 기능을 `Main.cpp`에 직접 추가하거나 Domain에서 콘솔 API를 호출하지 않는다.
